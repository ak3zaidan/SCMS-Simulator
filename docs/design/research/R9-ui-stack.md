## Cross-topic notes (facts only, drawn from rows above)

- Every "WebGPU" row from a library vendor carries an explicit caveat: deck.gl "not yet recommended for production"; PixiJS advises WebGL for production; three.js docs describe automatic WebGL 2 fallback and do not label the renderer stable. The browser-side Baseline claim (Jan 2026) comes from a third-party article.
- The only integrated-GPU instancing measurement found is the Quest 2 devlog (~2,600 instances, 55→~110 FPS after count-based culling + LOD). Desktop-class "1M instances" claims are demos without published FPS.
- Sharing one WebGL context between libraries is documented for MapLibre↔three.js (custom layer) and MapLibre↔deck.gl (interleaved), but not for deck.gl↔three.js.
- For the recording format, MCAP's chunk index + per-channel message index is the documented random-access path; keyframe+delta content design (GOP / ACMI style) is orthogonal and can be layered inside MCAP messages.
- SharedArrayBuffer for an engine-served browser UI requires the engine's HTTP server to send COOP/COEP; OffscreenCanvas is Baseline and transferable, so a render worker can own the canvas.
